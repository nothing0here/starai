# Agent 链路复查与工作台默认主题

> 后续更新：下文是最初审计快照。P1 提交中断恢复、P2 剩余阶段校验/冻结已在随后实施并通过回归，见 [Agent 恢复优化验收](agent-recovery-2026-09-03.md)。内容质量覆盖边界仍保留。

## Agent 结论

主流程已形成闭环，但异常恢复还不能称为完全闭环。本次只分析 Agent，不改执行、计费或任务状态。

| 阶段 | 现有实现与边界 |
| --- | --- |
| 意图理解 | 当前 LLM + 文字/媒体边界规则，区分讨论、提示词和执行请求；自然语言覆盖仍不是无限的 |
| 会话记忆 | 服务端草稿槽位、近期消息、较早历史摘录；换模型不清空草稿。不是跨项目知识库或无限长记忆 |
| 内容验收 | 模板/候选、部分明确约束、旁白字数检查，最多一次文字修复；不能保证所有事实或创意质量 |
| 模型能力与分段 | 按模型时长能力规划，执行前重校验；当前单成品最大 600 秒 |
| 用户确认 | 按会话与方案版本确认，原子占用状态和数据库唯一键防重复；旧版本不能直接执行 |
| 素材生成 | 分镜、关键帧、分段视频、配音分阶段保存检查点；已有成功素材复用 |
| 合成与交付 | 配音实测时长、共享时间余量、有上限调速；独立成品消息与折叠素材；历史恢复 |
| 故障恢复 | 已提交任务可凭确认键找回；原项目仅合成续传已有真实成功记录，但下列极端边界仍待补齐 |

## 尚未修复的具体缺口

### P1：确认被占用后、任务落库前崩溃，可能一直停留在提交中

`services/api/internal/service/agent_draft.go` 的 `ClaimAgentDraft` 先把草稿置为 `executing`；`GetAgentDraft` 只有查到带确认键的任务/工作流才恢复成 `submitted`。如果服务恰在占用后、创建任务前退出，没有任务可找回，现有逻辑不会自动释放；新一轮、重规划和取消也拒绝该状态。

这是代码中存在的崩溃窗口，不是在本次验收中真的制造了崩溃。

轻量补法：保存提交租约/开始时间，超时后先核对确认键与正在进行的提交；确认没有已创建或在途任务时恢复为待确认。必须保留幂等约束，不能仅按超时直接重发付费请求。

### P2：只补合成仍受完整模型配置与整单冻结额度限制

`services/api/internal/service/agent.go` 的 `retryProject` 在判断具体缺失阶段之前调用全模型校验，并用原项目 `estimated_cost` 执行 `FreezeWithFinalize`。所以即使素材已经齐全、不需要再次调用生成模型，也可能因为某个已不用的模型停用，或余额不足以冻结整单预估额度而无法续传。

上次正常余额下的合成续传没有新增媒体任务，也没有增加累计费用；上述问题是恢复门槛，不是已证实重复扣费。

轻量补法：先依据检查点生成“剩余工作清单”，只校验剩余阶段的模型、只冻结剩余预估费用；纯本地合成走零新增模型费用的路径。

### P2：质量不合格能够阻止执行，但还不保证自动修成可交付内容

文字稿修复有一次上限；Worker 的分镜质量门禁和配音时长门禁也可能停住。内容语义、角色连续性、事实真实性不能靠现有确定性规则完全覆盖。轻量方式应优先增加真实失败样本回归、明确可编辑失败字段和按节点补做，不必先上 RAG 或新的编排平台。

## 默认主题实现

入口：管理后台 → 系统配置 → 品牌设置 → 工作台默认主题 → 保存默认主题。

- 配置键 `workbench_default_theme`，仅允许 `dark` / `light`；未配置时默认为深色。
- 首屏由服务端获取公开配置，主题初始化脚本在工作台内容前应用；客户端导航及后续同步复用同一优先级。
- 有有效的原 `theme` 手动记录时优先使用它；没有记录的新用户、老用户都跟随后台。
- 后台默认值不会写成个人偏好，因此后台修改后，未手动选择的用户刷新仍可跟随。
- 沿用原有按浏览器保存的偏好，不新增用户字段、数据库迁移或依赖，不声称跨设备同步。
- 主题菜单只反映当前主题，不再用系统深浅色覆盖初始化。无限画布也跟随工作台主题。
- “保存默认主题”只提交这一项配置，不顺带覆盖其他系统配置。
- 管理后台自身主题不受影响；已经打开的工作台刷新后读取新默认，不做主动推送。

## 验收

- API 全测试通过，新增独立 SQL schema 的后台保存→公开配置读取测试；非法值及混合更新在写入前拒绝。
- Web / Admin TypeScript 检查通过。
- 主题测试 3 项、Agent 成品/历史测试 7 项通过；包含首屏脚本执行、默认不写入偏好、手动偏好优先、存储被禁用与非法配置回退。
- Worker 原有测试通过；本次不调用付费媒体模型。
- 浏览器实际保存浅色/深色，公开接口与服务端首屏脚本同步变化。
- 独立本地域名访客：首次深色 → 后台浅色后刷新变浅色；没有被默认写成个人偏好。随后手动深色在后台浅色下刷新保持深色。
- 已有 localhost 浅色偏好未被后台深色覆盖；最终后台默认保留为深色。

建议下一步按 P1 提交恢复 → P2 剩余阶段校验/计费 → 质量失败样本回归的顺序补齐。
