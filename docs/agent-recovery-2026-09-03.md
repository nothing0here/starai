# Agent 恢复优化验收 · 2026-09-03

## 已实施

- 填槽自修正：LLM 产生的可选参数不规范时，先规范常见画质/画幅/秒数；用户未指定画质时忽略错误推断并使用模型默认值。明确但不支持的要求会保留其他槽位并给出合法选项，修正后仍必须再次确认。
- 模型参数校验：待确认前按所选视频模型声明的画质、画幅能力检查；执行时再次校验，不能用供应商报错代替参数指导。
- 上下文引用：“把这四条/上述新闻做成视频”沿用已整理结果，不重复搜索或悄悄更换第4条；用户明确要求重新核验或更新时才搜索。

- 提交异常恢复：读取历史草稿时，先按确认键查找已创建的任务；找回后继续原任务。处于提交中超过 5 分钟且确实未落任务时，保留槽位和方案、升级版本，恢复待确认，不自动重发付费请求。
- 并发保护：任务/工作流落库（包括余额不足的失败记录）与恢复使用同一会话行锁和版本校验。迟到的旧请求不能在恢复后创建新任务，旧回调不能覆盖新方案。
- 历史界面展示恢复原因和重新确认入口。
- 漫剧续传按分镜 ID 检查关键帧、视频和配音，只校验仍需调用的模型，只预估缺失素材费用。已有成功素材与节点记录保留；重复 ID、失败项不被误算为成功。
- 仅剩本地合成且历史用量已结算时，新增模型预估为 0，不再要求旧模型可用或冻结整单额度。若历史确有未结算用量，则单独纳入预留，避免最后结算再失败。
- 首次估价与续传复用同一个估价实现；保存剩余工作清单、未结算金额和本次预估，便于排障。
- 提交续传前复核素材/参数快照；入队失败时回滚冻结，保留检查点。

## 实际验证

- 使用真实失败话术“把这四条热点新闻做成10秒9:16播报短视频”回归：错误的 `quality` 推断被忽略，10秒、9:16及内容均保留并进入待确认；8K会列出支持值且不能确认，回复“使用默认画质”后恢复同一方案。

- API 全包测试通过，包含独立 PostgreSQL schema 的真实事务测试。
- 草稿验证：新提交不误重置、过期提交恢复、旧版本/跨用户/未再次确认请求拒绝、旧回调不能覆盖、并发插入完成后正确找回原任务。
- 续传验证：零余额、旧模型全部停用、素材齐全仍到达入队；缺一条 6 秒视频时按新模型只冻结 12（测试单价 2/秒），不冻结原整单 100；历史未结算 5 单独预留；入队故障后冻结归零，素材和节点记录不变。
- 队列测试使用隔离的拒绝端点，验证失败回滚，不向真实 Worker 投递假任务，不调用付费模型。
- Worker 全包测试通过，使用本地 FFmpeg 跑音频相关测试。
- Web / Admin TypeScript 检查通过；成品/历史与主题相关 Node 测试共 10 项通过；`git diff --check` 通过。
- 本地 API 已重启至最新代码，`/health` 返回 API 和 Worker 正常。
- 真实业务数据未新增生成任务：tasks 112，workflow_projects 23；最近成功项目 `wfp_68fea126-259` 仍为 succeeded，累计费用仍为 2.190281。测试 schema 已清理。

## 边界

- 本轮重点是异常恢复与续传门槛；未新增 RAG、编排平台、依赖或数据库迁移。
- 五分钟恢复检查由读取草稿/历史触发，不是后台自动重发任务。恢复后仍需用户确认；模型或策略改变时仍需更新方案。
- 本轮没有重新购买生成一条成片，也没有模拟供应商实际宕机；真实素材合成成功记录见此前验收。供应商可用性、自然语言理解和生成内容质量不能由这些恢复测试保证。
- 现有单成品时长上限与分镜/音频质量门禁不变；更长剧集与更多语义失败样本另行完善。
